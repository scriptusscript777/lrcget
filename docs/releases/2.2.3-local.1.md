# LRCGET 2.2.3+local.1

Hover help now closes two seconds after it appears, even when the mouse stays
still. Native browser tooltips previously controlled their own lifetime.

Move away and return to read help again. Leaving, clicking, scrolling, Escape,
window blur, resizing or control removal closes it immediately. A short 350 ms
initial delay avoids flashing help while passing over controls. The passive,
viewport-bounded bubble never intercepts editing clicks; descriptions stay
available to assistive technology. Help text is literal, not HTML.

This covers editor descriptions and native titled controls throughout the app,
including dynamically added or updated controls. Menus, dialogs, marker warnings,
playback, zoom, lyric data and save/export behavior keep their existing operation.
All 2.2.2 features, including the moving-playhead fix, remain included.

## Linux compatibility

The behavior uses the shared frontend and does not depend on a Linux desktop
environment. The distributed package targets amd64 and requires glibc 2.39+,
GTK 3 and WebKitGTK 4.1. Its explicit libc dependency prevents installation on
older incompatible hosts. ARM and older distributions require separate builds.
Windows can use the shared code but no Windows installer was built/tested here.

## Validation

389 frontend tests passed, including updated description tests. Scoped ESLint,
Prettier, documentation links and diff checks passed. Browser checks verified
two-second expiry with a stationary pointer, no immediate reopening, re-entry,
Escape/click/scroll/leave, switching, dynamic/literal descriptions, removal,
viewport bounds, accessibility attributes and controller cleanup. Native WebKitGTK
event checks verified timeout/suppression in both themes using an isolated profile.
No user recordings, sidecars or live lyrics database were edited.

Ruff reports 11 existing findings in the unchanged Python fixture generator.
Existing Rust and bundle warnings remain. Installer and upgrade verification
are recorded in the [review](../reviews/2.2.3-local.1.md).

## Upgrade

Close LRCGET, then verify and install the downloaded package:

```bash
sha256sum -c LRCGET_2.2.3+local.1_amd64.deb.sha256
sudo apt install ./LRCGET_2.2.3+local.1_amd64.deb
```

It upgrades the same `lrcget` application, identifier and data location.
See the [how-tos](../how-to.md), [full features](../app-overview.md) and
[editing reference](../editing-guide.md).

Production Debian packaging and checksum verification passed. APT confirms this
is one upgrade with no additional app installation or package removal.
A [focused upstream proposal](https://github.com/tranxuanthang/lrcget/pull/426)
shares the hover-help fix separately from the fork's waveform editor.
