## Download and Install

[Linux amd64 installer](https://github.com/scriptusscript777/lrcget/releases/download/v2.2.0-local.8/LRCGET_2.2.0%2Blocal.8_amd64.deb)
and [SHA-256 checksum](https://github.com/scriptusscript777/lrcget/releases/download/v2.2.0-local.8/LRCGET_2.2.0%2Blocal.8_amd64.deb.sha256).
Close LRCGET normally before upgrading so unsaved edits are not lost.

```bash
sha256sum -c LRCGET_2.2.0+local.8_amd64.deb.sha256
sudo apt install ./LRCGET_2.2.0+local.8_amd64.deb
```

This upgrades the existing app, not a second installation. The package is
unsigned; Linux amd64 is the only installer built/tested for this release.
No additional decoder, WAV conversion or AI model is required.

## Cleaner Timing Editor

![Light-theme waveform and optional word editor](https://raw.githubusercontent.com/scriptusscript777/lrcget/v2.2.0-local.8/docs/screenshots/editor-follow-light.png)

The pink selected-word bubble below the word blocks is removed. Word text,
hover tooltips, active-word highlighting and divider editing remain available.
The word-timing view is collapsible and hidden initially. Open **Word timing**
when you need individual-word edits; phrase timing remains the main view.
Active-word highlighting and new controls respect light and dark themes.
The word-timing zoom slider enlarges the whole timeline without changing its
time scale or saved timestamps. During playback the view scrolls to keep the
current position visible. Paused inspection stays where you pan it.

The zoomed waveform now follows active playback, including backward seeks and
phrase loops. Paused panning remains available for inspecting another region.
Following uses the same player and cached peaks, not a second audio engine.
The crosshair button toggles following; it is enabled when the editor opens.

Selected synced phrases have start/end waveform handles for timing edits.
Completed drags use the editor's undo/redo history; canceled drags do not change
the document. Saving and exporting remain explicit actions.

1. Select a phrase in the Synced tab. Its visible boundaries appear as `[`/`]`
   handles in the waveform; there are no handles for every other lyric line.
2. Drag a handle to preview, then release to commit. Escape cancels the drag.
   Clicking without moving does not change timing.
3. Focus a handle and use Left/Right for the selected timing step, Shift+Left/Right
   for ten steps, or Home/End for the allowed boundary limits.
4. Moving the start shifts its existing word timing while holding its end fixed.
   The end handle cannot cut off existing word timestamps. Neither handle moves
   neighboring lines. Invalid/out-of-track boundaries are not editable here.
5. Use undo/redo to compare the edit, then save/export when ready.

![Zoomed word-timing view](https://raw.githubusercontent.com/scriptusscript777/lrcget/v2.2.0-local.8/docs/screenshots/word-timing-zoom.png)

The waveform represents the whole mix, not a vocal-only stem. It is a manual
editing aid, not proof of synchronization or automatic lyric alignment.
Peak-cache limits and format support are unchanged from
[the waveform release](2.2.0-local.7.md).

## Verification

- 235 frontend tests and 45 Rust tests passed.
- ESLint passed with no errors and 74 existing warnings. Rust release checks
  passed with existing compiler warnings. Ruff found no applicable Python files.
- Browser checks covered forward/backward playback following, paused cursors,
  word-view disclosure, linear zoom/scrolling, drag preview/commit/cancel,
  pointer identity, timing bounds, shortcuts and undo/redo.
- Light/dark checks covered readable active-word highlighting and controls,
  the 1024px desktop editor, and standalone 400px waveform/word-lane layouts.
- The Linux package built successfully. The compiled app passed isolated
  startup/F5 scanning and waveform generation/rendering checks.

Browser playback checks use mocked audio/backend events. Native checks use
generated fixture audio. No personal music/LRC files were modified, and these
tests do not prove lyric synchronization against real singing.
