## Logic and fixes

The initial false state prevents startup flashes. Database migration adds a checked
boolean without rewriting music or lyrics. Optional command input preserves the
choice for older callers; scoped setters avoid export/download preference conflicts.
A transaction keeps general settings and hover help together on failed saves.
The UI applies the immutable submitted snapshot only after persistence succeeds,
avoiding divergence if form controls change during the asynchronous save. Duplicate
Save is guarded; failure leaves the old runtime value and supports retry. Cancel
never applies the draft, and reopening reloads the stored preference.

The shared helper observes the saved global choice and cancels pending/displayed
help when it changes. The one-second hover callback rechecks the preference.
F1 requests help independently, after configured shortcuts, and ignores handled,
modified or repeated key presses. Existing dismissal and disposal paths release
timers, listeners, target references and the preference watcher. Dynamic titles
retain accessible names/descriptions; text is literal and pointer-transparent.

A browser test initially mixed stale Vite module instances after live edits.
Restarting the test server resolved the fixture issue; fresh tests and native
Settings checks verified that the actual saved runtime state is shared correctly.
The upstream port initially lacked the fork's existing tempfile dependency for
restart tests; it now declares that test dependency explicitly.
